Um "aplicativo web" pode ser só um editor de arquivos no seu computador.

Esta página é um editor de .docx (o formato do Word) completo: abre, exibe, edita e grava o arquivo de verdade — e é um único index.html, sem instalação, sem servidor e sem internet. O monitor ao lado registra cada byte que tentar sair. O QualiLab, no modo Arquivo, é exatamente esta arquitetura aplicada ao formato .qualilab.

O que isto prova

"Roda no navegador" ≠ "está na nuvem"

O navegador aqui é só o ambiente de execução — como o Windows é para o Word. Um arquivo HTML aberto do disco é um programa local. Servidor, conta e internet são escolhas de quem desenha o software, não consequências de ele ser "web".

Formato complexo, operação simples

.docx é um ZIP com XML dentro. Esta página descompacta, interpreta, edita e recompacta com ~algumas centenas de linhas de JavaScript puro — sem biblioteca externa. Abrir e gravar arquivo é operação de editor, não de plataforma.

Verificável, não prometido

A promessa de privacidade não está em texto de política, e sim em mecanismo: a página proíbe a si mesma de usar rede (CSP), o monitor registra tentativas, e o DevTools do seu navegador é o auditor independente.

Monitor de rede embutido + auditoria externa via F12 Seção "Onde os seus dados ficam" no README: a regra de ouro é o material só sai do seu dispositivo se você deixar

Honestidade no limite da analogia. Esta demonstração leva o princípio ao extremo: proíbe toda rede, para sempre. O QualiLab completo carrega bibliotecas de interface (CDN) ao abrir a página e oferece recursos opcionais que usam rede quando — e só quando — você os escolhe: modo Nuvem (Supabase, inclusive o seu), IA (desligada por padrão, com a sua chave, do navegador direto ao provedor) e busca semântica (o modelo é baixado uma vez para rodar local). A tese demonstrada aqui é a do modo Arquivo, o caminho recomendado para dados sensíveis: nele, o seu material faz o mesmo trajeto do .docx desta página — disco → memória do navegador → disco.
